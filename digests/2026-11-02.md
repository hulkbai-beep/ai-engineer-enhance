## 本周必读

- [ ] **[Trace Claude API requests and Managed Agents sessions with OpenTelemetry](https://platform.claude.com/cookbook/observability-opentelemetry-tracing)**（Claude Cookbook）：讲 anthropic Python SDK（1.14.0 起，beta）自带的 OpenTelemetry 追踪：注册 TracerProvider 后，Messages API 请求、流式输出、tool runner 循环和 Managed Agents 会话都会产生遵循 GenAI 语义约定的 span（模型、token 用量、缓存、首 token 时间、工具调用等），默认只导出元数据，content_mode 设为 content 才导出提示和回复；用标准的 OTEL_EXPORTER_OTLP_* 环境变量导到任意 OTLP 后端；在 Console 配置遥测目的地后，API 侧的模型运行、服务端工具、MCP 工具、上下文压缩等 span 会通过 traceparent 挂到同一条 trace 下。注意三处 span 报的是同一份用量，不要重复相加，计费以 Usage and Cost API 为准。
- [ ] **[Review your agents' sessions for security issues with Claude](https://platform.claude.com/cookbook/managed-agents-cma-agent-security-review)**（Claude Cookbook）：给已经结束的 agent 会话做安全复查：先为每个 agent 写一页职责说明和可机器检查的授权（允许的 host、凭据、工具、收件人），把 Managed Agents、Messages API 或 Agent SDK 的日志转成带来源标签的编号事件；不调模型先跑 60 条正则规则和 7 条结构规则（访问授权外的 host、用了没给的凭据、被拒后换个工具重试等），再用 Managed Agents 动态工作流让 Claude 并行逐个审查会话，代码校验每条证据引文确实出自它引用的事件，最后输出带引文的分级报告（Routine / Look / Act）。示例里有个 agent 照着发票 PDF 里埋的指令把数据经 web_fetch 发了出去；用 Haiku 5.5 审 20 个会话约 10 美分。它只能事后发现、不能拦截，适合作为提示注入和越权行为的巡检。
- [ ] **[Le Chonk: Built for Coders, Trusted by Defenders](https://mistral.ai/news/mistral-large-4-oss/)**（Mistral）：Mistral 把 Mistral Large 4（Le Chonk，Hugging Face 上是 Mistral-Large-4-1T-A52B，原生多模态的指令与推理混合 MoE，三档推理强度）以修改版 MIT 许可开放权重，主打 agentic 编程和防御性网络安全：Artificial Analysis Coding Agent Index 48%，与 GLM-5.3 持平但每个任务平均少用 47% 的 token，Terminal-Bench 4.0 41%（比预览版高 13 个点），恶意网络请求拒答率 96.6%。可以通过 Mistral API（mistral-large-4-0）、OpenRouter、Hugging Face 自部署（vLLM、SGLang）以及 NVIDIA 和 Microsoft Foundry 使用，每百万 token 输入 0.70 美元、输出 2.10 美元；做模型即服务的企业要另买商用许可。需要可自托管的强编程、agent 模型时值得评估。
- [ ] **[Managed Deep Agents v0.10: Browser use and asynchronous subagents](https://www.langchain.com/blog/managed-deep-agents-browser-use-and-asynchronous-subagents)**（LangChain Blog）：Managed Deep Agents v0.10（公开测试）新增两项：浏览器使用，浏览器跑在独立的 LangSmith 沙箱里，agent 多了 browser_snapshot、browser_run、browser_screenshot、browser_handoff 四个工具，登录状态按 thread 或 user 隔离，遇到登录或二次验证就把窗口交给人，密码不进模型消息和 trace；异步子 agent，在子 agent 定义里加 "async": True 就能在后台跑长任务，主 agent 可以启动、查看、更新、取消它，完成后不用轮询就会收到通知。另有 Slack 停止按钮、resolveUser 映射用户权限等；破坏性变更是 connectors.mcp() 被移除，MCP server 改在 tools/mcp.py 或 tools/mcp.ts 里声明。
- [ ] **[Browser Use in Managed Deep Agents](https://www.langchain.com/blog/browser-use-in-managed-deep-agents)**（LangChain Blog）：讲 Managed Deep Agents 的浏览器能力是怎么设计的：浏览器跑在和 agent 分开的 LangSmith 沙箱里，四个工具基于 Browserbase 开源的 Stagehand；browser_run 接受批量动作或 Playwright 风格代码，一次调用串起多步、只返回需要的结果，页面内容不进 agent 上下文；需要登录时用 handoff 交给人，密码不经过模型；做端到端测试时通过 localhost 桥接访问 agent 沙箱里的应用，跑通的步骤存成 Playwright 测试文件，之后不调模型直接回放。在 100 个 WebVoyager 任务上通过 90%、总成本 1.98 美元，是测试的 7 套工具里最高的（Browserbase MCP server 89%，成本是它的 9 倍）。
