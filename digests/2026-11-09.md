## 本周必读

- [ ] **[Agents Are Going Async](https://www.langchain.com/blog/agents-are-going-async)**（LangChain Blog）：LangChain 讲 Deep Agents（Python 和 JS）的异步子 agent：子 agent 在后台跑长任务，主 agent 继续回应用户。主 agent 用 start、check、update、cancel、list 五个 async_task 工具管理任务；子 agent 定义里的 update_strategy 决定追加指令时是中断后按新指令重跑（interrupt，默认）还是排队等当前任务结束（enqueue）；结果怎么送达取决于主 agent 的状态：忙时每次调模型前检查、空闲时由子 agent 唤醒一次新运行、等人工审批时在用户答复后送达。在 define_deep_agent 里把 async 设为 True 即可开启，任务通知还是 beta。需要跑长任务又不想卡住对话的 agent 可以照这个模式做。
- [ ] **[The components of agent memory](https://www.anthropic.com/research/components-of-agent-memory)**（Anthropic Engineering）：Anthropic 把 agent 记忆定义为 Claude 从经验中得到、跨会话保留、之后能读回上下文的知识（不含改权重、上下文内学习和压缩），分成四层：可检索的会话记录、记忆笔记、wiki 之类的记忆表示、每次会话都注入的上下文；并介绍 dreaming：离线翻看日志和会话记录，纠正错误、写笔记、建 wiki，再把笔记提升为注入上下文。在 CL-Bench 1.0 的数据库任务上，加了记忆后 Opus 5 的平均奖励从 0.564 升到 0.828，Opus 5.5 从 0.655 升到 0.838；只记录失败的规则会让 Opus 5 的增益少 0.234。注入的记忆占上下文，错误的笔记会带进每次会话，所以顶层要保持精简（Claude Code 的 auto memory 只加载 MEMORY.md 的前 200 行或 25 KB）。给 agent 设计记忆层时可以按这套分层来。
- [ ] **[Latency Optimization on the Claude API](https://platform.claude.com/cookbook/latency-optimization-latency-optimization)**（Claude Cookbook）：Claude API 延迟优化指南：把总耗时拆成「调用次数 × 首 token 时间 + 输出 token ÷ 输出速度 + 其他」，跟踪 p50 和 p90，并用一个 154 题的保险理赔 agent 评测守住准确率。基线 Opus 5.5 medium effort 为 p50 6.1 秒、p90 11.3 秒、99.0% 正确、每题 0.2512 美元；开 prompt caching 后每题降到 0.0377 美元，延迟和准确率基本不变；message threads 在一个例子里把请求从 22.3 MB 缩到 0.3 KB、首 token 时间从 1.27 秒降到 0.63 秒；fast mode 价格约翻倍，p50 和 p90 降 53%-59%；限定输出格式（如只答两行）把一次决策从 46.4 秒降到 4.9 秒。建议先建好带质量线的 eval 再动延迟杠杆，因为不少杠杆是拿准确率或成本换速度。
- [ ] **[Dreaming with a dynamic workflow](https://platform.claude.com/cookbook/managed-agents-cma-dreaming-with-a-dynamic-workflow)**（Claude Cookbook）：用 Managed Agents 动态工作流实现 dreaming：读取已结束的会话记录，整理成 wiki 式的记忆库（一组互相链接的小文件加 _index.md），之后的会话只读挂载。主 agent memory-distiller 默认用 claude-sonnet-5-5，transcript-analyzer 和 memory-organizer 默认用 claude-haiku-5-5；11 份示例记录（283 KB）约 2.5 分钟、0.36 美元，50 份长记录（约 12 MB）约 8 美元，可以用 cron 每晚跑。会话记录按不可信输入处理：挂载记忆的 agent 只读，分析 agent 的网络白名单为空；Managed Agents 会话不适用零数据保留和 HIPAA。想给 agent 加跨会话记忆的可以照着搭。
- [ ] **[New context engineering challenges in late 2026](https://www.langchain.com/blog/context-engineering-challenges-late-2026)**（LangChain Blog）：Harrison Chase 认为 agent 正收敛成「LLM 在沙箱里循环调用工具」，常规的上下文工程手段已经成型：长对话摘要、大工具结果外置、用 skills 渐进披露、工具搜索、用子 agent 隔离上下文、以 bash 为主工具。常驻、主动型 agent 还有几个没解决的问题：主动但不烦人、该记住什么、后台任务完成（包括暂停等审批时）怎么通知主 agent、目标跟踪、agent 钻目标的空子、浏览器操作用截图还是 DOM 作上下文。没有代码，适合当作长时运行 agent 的设计清单。
