## 本周必读

- [ ] **[Why Agents Are Soon Only Going to Have 1 Tool](https://www.philschmid.de/code-mode)**（Philipp Schmid）：Philipp Schmid 讲 agent 正在把整个工具目录收拢成一个 exec(code) 工具（Code Mode，也叫 Programmatic Tool Calling）：模型不再每轮只发一个 JSON 工具调用、等结果、再推理，而是写一小段 TypeScript 或 Python 在隔离沙箱里串联、过滤、并发执行多个动作，适合检索筛选、多文件修改加就地验证、浏览器操作和并行子任务。文中用 Gemini Interactions API 搭了一个单工具 agent，并指出 Pi、Factory Droid、OpenAI Codex 已默认或支持 Code Mode（Factory 切换后 Terminal-Bench 4 提高 3.5 分、模型开销降 15%），Pydantic AI、LangChain、Cloudflare Agents SDK 也有类似工具；现有为 bash 和人类可读文本设计的工具、CLI 和 skills 可能需要重新审视。
- [ ] **[Cost per task: Using cheap classifiers to route across Gemini models and thinking levels](https://developers.googleblog.com/cost-per-task-using-cheap-classifiers-to-route-across-gemini-models-and-thinking-levels/)**（Google Developers Blog）：主张用「每个成功任务的成本」而不是 token 单价衡量 agent，并用 50 道自动评分的编码 agent 题实测在 Gemini 前面加 Jev 分类器做路由：笼统地问「简单还是复杂」几乎全判成简单，拆成一个原子的是非题才有效；按关键词和长度写的规则在开发集上 93.8%，到没见过的任务上掉到 70.6%；限制 maxOutputTokens 并不会让模型少思考，反而弄坏了 7 道难题。结论是先试 Flash 低思考档（已能全对且便宜得多），再用分类器把难题送去更强的配置。
- [ ] **[Introducing Claude Fable 5.2 and Claude Mythos 5.2](https://www.anthropic.com/claude-fable-and-mythos-5-2)**（Anthropic News）：Anthropic 发布 Claude Fable 5.2 和 Claude Mythos 5.2：两者是同一个底层模型，Fable 带网络安全和生物方面的防护、面向所有用户，Mythos 只开放给通过生命科学或网络安全验证计划的机构。输出速度比 5.1 快最多 30%，价格降到每百万 token 输入 8 美元、输出 40 美元，可选 fast mode（最高 2.5 倍速度，16/80 美元）。官方基准上几乎全面领先 Opus 5.5：FrontierCode 2.0 49.1%（Opus 5.5 为 45.5%）、FrontierSWE v2 69.9%、OSWorld 2.1 89.3%、Remote Labor Index 41.3%。官方建议多数编码和知识工作先用 Opus 5.5，不够再升到 Fable；Fable 5.2 也可以当 Advisor（小模型遇到难题时向它求助）或 Orchestrator（把简单任务分给小模型）。
- [ ] **[Claude Fable 5.2 and Claude Mythos 5.2 on the Claude API: four breaking changes from Fable 5.1](https://platform.claude.com/docs/en/models/fable-5-2/whats-new-fable-5-2)**（Claude API release notes）：claude-fable-5-2 和 claude-mythos-5-2 上线：1M 上下文、128k 最大输出、自适应思考常开（用 effort 控制深度）。从 Fable 5.1 迁移有四个破坏性变化：前缀检查失败直接返回 400，改了 system、tools 或之前的消息后再发回 5.2 的 thinking block 就会报错（可临时加 thinking-binding-controls-2026-08-01 beta 头、把 prefix_mismatch_behavior 设为 drop_block，代价是输出 token 增加）；只有 Fable/Mythos 5.2 能读 5.2 的 thinking block，切到其他模型这部分推理会被丢弃；computer use 要改用 computer_toolset_20260801，旧的 computer_20251124 除 Bedrock 外都报 400；advisor 工具里 5.2 执行者只接受 5.2 当 advisor。经 Claude Code、Managed Agents 或 Agent SDK 发请求的不受影响，自己拼请求、会改历史消息的 agent 切换前要先测。
- [ ] **[Gemini Decision 1 and the Decisions API](https://aistudio.google.com/docs/decisions-api)**（Gemini API changelog）：新的 Decisions API 用 gemini-decision-1 对文本、JSON、PDF、音频、图片和视频回答类型化的问题：是/否（noul，返回 0.01 到 0.99 的概率）、单选（choice）和按评分等级打分（score），都附 confidence；不生成文本，输出 token 恒为 0，多个问题在一次前向里并行计算、互相看不到，延迟几乎不随问题数增加。官方建议把问题拆成单一用途的原子检查，在代码里用 if 和权重组合，再按 confidence 决定自动执行还是转人工。做分类、路由、审核或 LLM-as-judge 的，可以用它代替「生成文本再解析」；需要 google-genai SDK 3.2 以上。
